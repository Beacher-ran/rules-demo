# rules_demo · Trae / WorkBuddy 规则示例

演示「把团队规范写成规则文件，让 AI 每次都按同一套标准产出」。
规则文件放在 `.trae/rules/` 下，IDE 会在匹配场景自动加载，不需要每次对话重复交代。

---

## 目录结构

```
rules_demo/
├── README.md                      # 本说明
├── 示例-合规与违规对照.md          # 同一需求在「无规则 / 有规则」下的产出差异
└── .trae/rules/
    ├── 代码编码规则.md             # 写代码时生效
    ├── 中文文档写作规则.md         # 写文档/报告时生效
    └── 接口设计规则.md             # 改接口定义时生效
```

---

## 规则文件的三个开关

每个规则文件顶部是 YAML front matter，决定它什么时候被加载：

| 字段 | 取值 | 含义 |
|------|------|------|
| `alwaysApply` | `true` | 每次对话都加载（适合团队基础规范） |
| | `false` | 只在 `description` 描述匹配时加载 |
| `description` | 一句话 | 说明适用场景，AI 靠它判断要不要用 |
| `globs` | 路径模式 | 命中文件路径时加载（如 `**/*.yaml`） |

示例：

```markdown
---
alwaysApply: false
description: 编写或审阅 Markdown 文档时使用
---
正文写具体要求……
```

## 本目录里的三条规则

| 规则 | 触发时机 | 管什么 |
|------|----------|--------|
| `代码编码规则.md` | 写代码（alwaysApply: true） | 英文命名、中文注释、函数前必写注释、错误处理 |
| `中文文档写作规则.md` | 写/改 Markdown 文档 | 标题层级、表格优先、R2 不用上标、数字标来源 |
| `接口设计规则.md` | 改 `*.yaml` / 接口文档 | 命名风格、必填字段、错误码、版本与兼容性 |

---

## 怎么验证规则真的生效

1. 用 IDE 打开本目录，随便打开一个文件；
2. 提问：「按这个目录的规则，帮我写一个读取 CSV 并输出统计量的 Python 函数」；
3. 观察输出是否满足：英文命名 + 函数前中文注释 + 关键步骤注释 + 显式异常处理；
4. 对比 `示例-合规与违规对照.md` 里的「无规则」版本，差异就是规则的价值。

> 规则不是提示词：提示词是"请求"，模型可以无视；规则是每次进上下文的约束，
> 能显著降低输出风格的随机性——但涉及正确性（安全、合规、数值）时，仍然要靠代码兜底。
